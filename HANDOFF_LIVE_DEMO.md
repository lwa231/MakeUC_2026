## 1. Goal and the one rule

Connect the Arduino accelerometer stream (Python side, `serial_bridge.py`) to the C++ OpenGL 3D viewer (`main.cpp`) using their existing variables and code. **Do not edit `main.cpp`, `fake_pi.py`, `serial_bridge.py` or `camera_origin.py`**; glue goes in `live/` as new scripts. Ask the user before breaking this rule. (Their reasoning: the existing code already works; only connect it.)

*Update (sensor-smoothing branch):* `fake_pi.py` is deleted (`live/mock_sensors.py` replaces it) and `main.cpp` now also reads `K`/`M` lines from `leg_filter.py` (smooth playout, keys `C [ ] ; ' V Z`); its old 7-field path still works.

They were already compatible at the data level: the bridge prints `t_ms,thigh_x,thigh_y,thigh_z,shank_x,shank_y,shank_z[,4 position cols]` to stdout and `main.cpp` popen()s any `--pi-cmd` command and `sscanf`s the first 7 fields (extra fields and non-sample lines are ignored). What was missing was a way to build and launch them together on a Mac.

## 2. Data flow (as launched)

```
Arduino (MMA7660 x2) --USB 115200--> serial_bridge.py --stdout--> live/leg_filter.py --K/M lines--> build/viewer (main.cpp via popen --pi-cmd)
  (--demo: live/mock_sensors.py, which also writes the camera file)      ^  knee_estimator.py (Kalman filter: accel + late camera frames)
                                                                         |  calibrate.py (Hang and Straighten, Anchor, Bench check)
  build/leg_state.json{,.cam,.tune} <-- live/leg_panel.py (leg switch, webcam/ArUco, Fusion card; Tk)
  build/leg_state.json.viewer <-- viewer keys;  build/leg_state.json.stats <-- leg_filter (2 Hz, read by the panel)
```

`live/run_live.py` assembles and launches all of it.

## 4. How to run

```bash
cd /Users/luqman_ahmed/Desktop/MakeUC2026/repo
python3 live/run_live.py --pretty-check      # data only, no window; expect ~100 Hz
python3 live/run_live.py                     # opens the LEFT/RIGHT window, then the viewer
python3 live/run_live.py --leg right         # skip the choice
python3 live/run_live.py --demo              # mock brace + camera (live/mock_sensors.py), no hardware
python3 live/sensor_check.py                 # Arduino's own sensor self-check
python3 live/verify_pipeline.py --skip-silent   # no-hardware regression test
bash live/build_viewer.sh                    # rebuild the viewer (needed after any main.cpp edit)
```

Other `run_live.py` flags: `--port P`, `--camera [N]`, `--no-position`, `--log f.csv`, `--viewer-args "..."`, `--bridge-args "..."`, `--kill-stale`, `--dry-run`, `--no-panel`, `--no-install`. Exit code 3 = serial port busy (it names the holder; usually the Arduino IDE Serial Monitor). Viewer keys: C calibrate, Z quick zero (only if truly straight), `[ ]` camera weight, `; '` responsiveness, V source (fused / sensors / camera), SPACE toggle auto demo, R reset, LEFT/RIGHT orbit, ESC quit. Calibrate each session: sit, press C, let the shin hang, straighten and hold, hang again (~35 s); see `live/README_LIVE.md`. `--demo --scenario calib` plays a calibration session (press C at the start).

## 5. Left/right leg (latest change)

User report: on the **left** leg the model is right side up; on the **right** leg it is upside down ("shin where the thigh should be and vice versa").

`main.cpp` shows only the knee angle `wrapDeg(kKneeSign * (tilt(shank) - tilt(thigh)) - zeroOffset)`, clamped to 0..120 for display, with `tilt = atan2(sag, vert)`, `kSagAxis=0 (x)`, `kVertAxis=2 (z)`. Axis map is compile-time.

Implemented in the filter (state in `build/leg_state.json`):
- `invert`: negate x (and the x position columns) of both sensors -> knee angle sign flips. **Default ON for right leg**, OFF for left. This is a physics-based guess (moving the brace to the other leg mirrors the lateral side); **it has not been tried on a real right leg.**
- `rot180`: negate x and z of the shank sensor -> shin tilt +180 deg. Default OFF. Try it if the shin looks folded back over the thigh.
- The user can flip both live from the window. Also: pressing **Z** with the leg straight absorbs any constant offset (a plain 180 deg offset may be fixed by Z alone; the user may not have pressed Z yet).
- Because a negative knee angle is clamped to 0, a wrongly signed right leg looks "stuck straight", not upside down. If the real symptom persists after `invert` and `rot180`, measure instead of guessing: close the viewer, run `python3 serial_bridge.py --port /dev/cu.usbmodem11401 --pretty` with the brace on the right leg, bend the knee, and see which axes swing; then decide on a change (a real fix may need `kSagAxis/kVertAxis/kKneeSign` in `main.cpp` plus `build_viewer.sh`, which needs the user's OK).
- `--demo` defaults to the left leg (the mock is a left leg); with `--leg right` it reads inverted until calibrated. A completed calibration replaces invert/rot180 (it finds the bend sign itself).

6. **Known limitations:** resolution is 0.047 g/count (~2.7 deg tilt steps), no gyro, keep exercise slow; do not press Z across a bridge reconnect (t_ms restarts; zeroing runs long); a truncated last field is not detected (no checksum); SIGTERM/SIGHUP on the bridge skip the `X` stop command (harmless); `--camera` never run on a real webcam; Windows untested for the new scripts (`leg_filter.py` uses `select` on a pipe, which does not work on Windows; the viewer/popen path itself is cross-platform).
